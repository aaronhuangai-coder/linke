# Linke V0.22 备份版本一致性面板设计

## 目标

V0.22 在 Web Console 中新增“备份版本一致性”只读面板，帮助用户从多台设备的历史 snapshot 中判断同一备份任务的最新版本是否一致。该功能贴近 Linke 的“数据版本统一”目标，但仍停留在原型阶段的可视化检查，不执行同步、恢复、删除、NAS 连接或远程传输。

## 范围

- 复用现有 `/api/devices` 响应获取设备列表。
- 复用现有 `/api/devices/:deviceId/snapshots` 响应获取每台设备的 snapshot 元数据。
- 在前端按任务分组并生成一致性分类。
- 新增 Web Console 面板、样式、单元测试、DOM 契约测试和 README 文档。

## 非目标

- 不新增后端 API。
- 不新增数据写入。
- 不执行真实同步。
- 不处理文件版本冲突。
- 不读取文件内容或比较文件 hash。
- 不连接 NAS，不调用 NAS app，不执行远程文件传输。

## 分组规则

每个 snapshot 只归入一个任务组：

- 若 `jobName` 存在，按 `jobName` 分组。
- 若 `jobName` 缺失，按 `sourcePath` 分组。

每个设备在一个任务组内只取最新 snapshot。最新判定沿用现有 snapshot 创建时间解析逻辑。

## 分类规则

- `一致`：多台设备都有该任务快照，且每台设备最新 snapshot 的创建时间和文件数一致。
- `版本不一致`：多台设备都有该任务快照，但最新 snapshot 的创建时间或文件数不同。
- `单设备`：只有一台设备存在该任务快照，无法进行跨设备一致性比较。

列表排序：

1. 版本不一致
2. 单设备
3. 一致

同类内按最新备份时间倒序，再按任务名称和 sourcePath 排序。

## UI 行为

面板展示四个汇总计数：

- 一致
- 不一致
- 单设备
- 任务组

每个任务组展示：

- jobName
- sourcePath
- 状态标签
- 分类原因
- 最新备份时间
- 总 snapshot 数
- 每台相关设备的 hostname、版本状态、最新备份时间和文件数

所有动态文本必须使用 `textContent` 渲染，不允许把设备名、任务名、路径或时间拼进 `innerHTML`。

## 安全边界

该面板是前端只读派生视图：

- 不新增 API。
- 不写入 metadata。
- 不保存一致性结果。
- 不触发备份。
- 不执行同步。
- 不执行恢复。
- 不删除快照。
- 不连接 NAS。
- 不调用 NAS app。
- 不执行远程文件传输。

## 验收标准

- HTML 包含 `version-consistency-panel` 与必需 data-testid hook。
- 面板没有执行按钮。
- 安全文案声明只读、不写 metadata、不触发备份、不执行同步、不执行恢复、不连接 NAS。
- 纯函数能分类 `一致`、`版本不一致`、`单设备`。
- `initConsole()` 加载设备后会只读请求各设备 snapshots 并渲染一致性面板。
- 动态任务名和 sourcePath 使用 `textContent` 渲染。
- README 当前版本为 V0.22，并说明 V0.22 仍不实现多设备自动同步。
